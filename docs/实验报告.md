# 机器学习课程大作业实验报告

B 类：Octo-Small 1.5 的动作头与全量微调，SimplerEnv WidowX 闭环评测。2026-10-24。

**项目类别：** B 类（工程实践型）
**完成方式：** 小组合作。训练与评测分工见仓库 README。
**代码仓库：** <https://github.com/ZhouMuYun1/octo-finetune-course>

## 1. 项目概述

本实验以公开模型 Octo-Small 1.5 为 Base，在 BridgeData V2 的 WidowX 子集上做了两次轻量微调：一次只训练扩散动作头（Final-A，head_only），一次训练全部参数（Final-B，full）。两次训练都跑了 1000 步，提交用的 checkpoint 统一取 step 750。正式对比包含两个任务。

- T1：`widowx_spoon_on_towel`，把勺子放到毛巾上；
- T2：`widowx_put_eggplant_in_basket`，把茄子放进黄色篮子。

Base、Final-A、Final-B 使用同一份评测脚本和同一组正式初始状态，每个模型每个任务 10 个 episode，共 60 个 episode。结果如下。

| 模型 | T1 | T2 | B-SimplerScore |
| --- | ---: | ---: | ---: |
| Base | 0/10 | 3/10 | 15.0 |
| Final-A（head_only, step 750） | 0/10 | 0/10 | 0.0 |
| Final-B（full, step 750） | 0/10 | 0/10 | 0.0 |

两个微调版本都没有带来正收益。Final-A 相对 Base 下降 15.0 个百分点，Final-B 也是 15.0。T2 上 Base 的三次成功集中在 ep0、ep3、ep9，失败 episode 全部跑满 120 步。T1 上 Base 自己也一次都没成功。

## 2. 模型与动作接口

Octo-Small 1.5 由一个 SigLIP 视觉编码器、一个投影后的 Transformer 和一个扩散动作头组成，总参数约 27M。Base checkpoint 是 `rail-berkeley/octo-small-1.5` 的 step 300000，已经在 Open X-Embodiment 上训练过，其中包含 BridgeData V2 的 WidowX 轨迹，满足"已经用 WidowX 数据训练"的要求。选择它是因为它的规模小，单卡 8GB 显存就能微调，并且论文里已经报告了 SimplerEnv WidowX 的闭环数字。

动作接口写在 `scripts/octo_bridge_policy.py`，三次评测用的是同一版本。Octo 一次预测 4 步 7 维动作，环境按 5 Hz 逐步取出来用。前 3 维是末端平移增量，第 4 到第 6 维是旋转增量，第 7 维是夹爪。评测时把模型输出的动作乘以一个 action scale（正式跑用 0.8），夹爪维以 0.5 为阈值二值化，大于等于 0.5 闭合，否则张开。图像缩放到 256×256。

推理用 `OctoModel.load_pretrained` 直接加载 orbax checkpoint，不经过 SimplerEnv 自带的 `OctoInference` wrapper。Base 和两个 Final 在独立进程中分别加载，避免 JAX 显存残留。

## 3. 数据与处理

训练数据来自 BridgeData V2 的 TFDS 发布 `bridge_dataset/1.0.0`，采集平台是 WidowX 250s。实验没有重新抽子集，直接用 BridgeData V2 里和"表面放置 / 容器放置"相关的分片。最终训练集 1404 条轨迹、验证集 156 条轨迹。没有按任务关键词二次过滤，也没有删静止帧。

字段对应关系如下。

- `observation/image_0` 作为主相机画面，resize 到 256×256。
- `observation/image_1` 作为腕部相机画面，resize 到 128×128。
- `language_instruction` 直接作为文本任务描述。
- `action` 是 7 维连续动作，按训练集自己的 mean/std 归一化到零均值单位方差。这个统计量和 Base 自带的 Bridge 全体统计量不同，所以评测时必须用 Final checkpoint 附带的 `dataset_statistics.json` 做反归一化。

正式评测的初始状态没有进入训练数据。训练轨迹来自 Bridge 遥操作记录，评测初始状态由 SimplerEnv 按固定的 `configs/eval_config.json` 生成。

## 4. 两次微调

两次训练都从同一个 Base 开始，优化器 AdamW，batch size 8，梯度裁剪 1.0。学习率峰值 3e-4，前 200 步线性 warmup，之后余弦衰减到 0。设备是一张 RTX 4090。

### 4.1 Final-A（head_only）

Final-A 冻结整个 Transformer，只训练扩散动作头。Octo 里可训练的叶子张量数是 27 / 366，其余 339 个叶子被冻结。计划 1000 步，每 250 步保存一次 checkpoint。日志在 `logs/train_log_head_only.txt`。

训练 loss 在 step 50 是 1.28，step 100 跳到 2.88，之后在 1.5 到 3.5 之间震荡，到 step 900 降到 0.92，step 1000 又回到 1.60。整条曲线没有稳定的下降趋势，2000 步的 warmup 都还没走完就到了计划步数。这说明 1000 步太短，动作头还没在小数据集上稳定收敛。

按"步数一致、方便对比"的原则，评测用 step 750 的 checkpoint。step 1000 保存时发生 OOM 崩溃，最后一个完整 checkpoint 就是 750。

### 4.2 Final-B（full）

Final-B 不做任何冻结，366 / 366 个叶子全部参与训练。其他超参和 Final-A 完全一致。日志在 `logs/train_log_full.txt`。同样在 step 1000 保存时因 OOM 中断，评测用 step 750。

全量训练的可训练参数比 head_only 多一个数量级，但训练数据量没变，短步数下更容易过拟合到小训练集。这一点在后面的闭环结果里也能看出来。

## 5. 评测设置

| 项目 | 设置 |
| --- | --- |
| SimplerEnv | 本地 commit `c701ea2` |
| 任务设置 | WidowX Visual Matching |
| 控制频率 | 5 Hz |
| T1 最大步数 | 60 |
| T2 最大步数 | 120 |

| 夹爪阈值 | 0.5 |
| 模型随机性 | 确定性采样（greedy） |

正式初始状态固定写在 `configs/eval_config.json`，三个模型共用。每个模型两个任务各 10 个 episode，共 60 个 episode。三次评测由同一个 `evaluate.py` 脚本驱动，逐 episode 结果写在 `results/b_formal/episodes.csv`。所有 episode 的 exception 字段为空。

## 6. 实验结果

| 模型 | 训练模块 | T1 成功数 | T2 成功数 | B-SimplerScore |
| --- | --- | ---: | ---: | ---: |
| Base | 未微调 | 0/10 | 3/10 | 15.0 |
| Final-A | 动作头（27/366 叶子） | 0/10 | 0/10 | 0.0 |
| Final-B | 全量（366/366 叶子） | 0/10 | 0/10 | 0.0 |

Base 在 T2 上的三次成功分别是 ep00（41 步）、ep03（54 步）、ep09（43 步），平均 46 步。失败的 7 个 T2 episode 全部跑满 120 步。T1 上 10 个 episode 全部跑满 60 步，没有一次成功。

Final-A 和 Final-B 在两个任务上 40 个 episode 全部超时失败。视频里能看到两种典型失败：一种是末端在物体上方就提前闭合夹爪，没有真正抓到；另一种是动作幅度太小，机器人在原地抖动，始终没有把物体移到目标位置。这两种失败在 Base 的失败 episode 里也出现过，但 Base 还有少数几次能成功抓取并搬运。

有证据的观察有三条。

1. 1000 步训练对 Octo 这个规模来说偏短。Final-A 的训练 loss 到 step 1000 还在 0.9 到 3.5 之间震荡，没有收敛迹象。Octo 官方微调脚本的默认 warmup 就是 2000 步，我们连 warmup 都没走完。
2. 数据量偏小。1404 条轨迹对全量微调（Final-B）远远不够，模型很容易过拟合到训练分布，反而丢失 Base 在 OXE 上学到的泛化动作先验。
3. T1（勺子放毛巾）比 T2（茄子放篮子）更难。Base 在 T2 上还有 30% 成功率，T1 是 0。勺子是长条形物体，夹爪的抓取位置要求更准，10 次评测里 Base 一次都没抓起来过。

## 7. 案例分析

下面三个 episode 来自正式评测，视频在 `results/b_formal/representative/`。

### 7.1 Base 在 T2、ep09 上成功

Base 用 43 步把茄子放进黄色篮子。视频里夹爪下降到茄子上方、闭合，抬起后横向移动到篮子上方再松开。这是 Base 在 T2 上三次成功之一。

### 7.2 Base 在 T1、ep00 上失败

Base 运行满 60 步。视频里夹爪在勺子上方大约几厘米的位置就闭合了，没有真的碰到勺子，然后在桌面上方空夹着移动。最后勺子还在原位，毛巾也没被碰到。T1 的 10 个 episode 基本都是这一类失败：夹爪闭合时机太早，下落距离不够。

### 7.3 Final-A 在 T2、ep03 上失败

Final-A 运行满 120 步。视频里夹爪对着茄子方向移动，但动作幅度明显偏小，末端在茄子旁边来回抖动，始终没有形成有效抓取。同样的初始状态下 Base 是成功的。这一步的退化说明 head_only 微调把 Base 原本能完成的动作分布改坏了，即使只训练动作头。

## 8. 局限

每个任务只有 10 个 episode，Base 在 T2 上的 30% 本身就在大幅波动范围内。两次训练各只有一次运行，没有换种子重跑。训练 loss 没有收敛，step 750 的 checkpoint 不是严格意义上的最优；如果继续训练到 5000 步以上，结果可能会不一样，但我们的算力和时间不允许。

评测时动作用了 action scale 0.8 和夹爪阈值 0.5，这两个参数是开发阶段在少量 episode 上调出来的，没有做正式的网格搜索。和论文里的数字对比时，需要同时核对初始状态数量、环境版本和步数上限。

## 9. 复现信息

- Base 权重：<https://huggingface.co/rail-berkeley/octo-small-1.5>，step 300000。
- Final-A 与 Final-B checkpoint：百度网盘链接见 `checkpoint_link.txt`。
- 训练：`bash train.sh`，配置在 `train_config.py`。
- 评测：`python evaluate.py --model-name Base --model-type octo-small --task widowx_spoon_on_towel --episodes 10 --eval-config configs/eval_config.json --output-dir results/b_formal/base --action-scale 0.8 --gripper-threshold 0.5 --record-video`。
- 逐 episode 结果：`results/b_formal/episodes.csv`。
- 代表视频：`results/b_formal/representative/`。
